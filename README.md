# טפסי התחייבות לאקסל

מערכת שקולטת טפסי התחייבות (PDF סרוק / תמונה מהטלפון), מחלצת מהם את השדות בעזרת
מודל ראייה (Gemini), מסמנת שדות לא בטוחים, מאפשרת בדיקה ותיקון, ומייצאת לאקסל.

## הפעלה מקומית
```bash
pip install -r requirements.txt
cp .env.example .env        # ולהשלים GEMINI_API_KEY
streamlit run app.py
```

## מבנה
| קובץ | תפקיד |
|---|---|
| `app.py` | ממשק Streamlit (RTL), טבלת בקרה, ייצוא |
| `lab_extractor/image_utils.py` | PDF -> תמונות (PyMuPDF), יישור הטיה וחידוד בצבע (OpenCV) |
| `lab_extractor/prompts.py` | ההנחיות למודל: איפה כל שדה, "לא מנחשים", כמה מספרים |
| `lab_extractor/extractor.py` | קריאה ל-Gemini עם פלט מובנה (Pydantic), ניסיונות חוזרים |
| `lab_extractor/validation.py` | אפסים לת.ז., נרמול ובדיקת תאריך, התאמה לרשימה סגורה, מיזוג עמודי המשך |
| `lab_extractor/pipeline.py` | קובץ -> עמודים -> חילוץ במקביל -> נרמול -> מיזוג |
| `lab_extractor/db.py` | SQLite (`lab_data.db`), כל הגישה דרך מחלקה אחת |
| `lab_extractor/exporter.py` | אקסל RTL, ת.ז. כטקסט, תאריכים אמיתיים |
| `lab_extractor/sending_entities.txt` | הרשימה הסגורה של גורמים שולחים - ניתנת לעריכה בלי קוד |

## כללים שמומשו
- שדה שלא נמצא נשאר ריק ומסומן. אין ניחושים.
- כמה מספרים מרכזיים / מספרי התחייבות נשמרים באותו שדה, מופרדים ברווח.
- ת.ז. מושלמת ל-9 ספרות עם אפסים מובילים ונשמרת כטקסט.
- שדה לא ודאי (לפי המודל או לפי בדיקות בקוד) מודגש בכתום, והרשומה בסטטוס "ממתין לבדיקה".
- עריכת תא בטבלה שומרת במסד ומעבירה את הרשומה ל"אושר".
- עמוד המשך מזוהה ע"י המודל וממוזג לטופס הקודם **באותו PDF**.

## העלאה לאינטרנט
- הקוד קורא הגדרות ממשתני סביבה / `st.secrets`, ויש `Dockerfile` (קורא `PORT`).
- **שמירת נתונים:** SQLite כותב לדיסק. ב-Streamlit Community Cloud הדיסק זמני; בשרת/Docker יש
  לחבר volume ל-`/app/data`. אם תרצו מסד משותף, מחליפים את `lab_extractor/db.py` ל-PostgreSQL.
- **אבטחה (חובה לפני חשיפה לרשת):** כרגע אין הגנה על הגישה, והמערכת מכילה פרטים אישיים.
  מוסיפים התחברות (או שמים מאחורי VPN / proxy עם אימות) לפני שמעלים.
- תמונות הטפסים לא נשמרות בדיסק - רק בזיכרון הסשן, לצורך תצוגה מול השורה.
